# Цель этапа

Перенести снабжение в EnterpriseOS и построить сквозную систему:

```text
Заявки
→ обработка
→ перемещения
→ долги
→ закупки
→ поставщики
→ накладные
→ оплаты
→ приёмка
→ iiko
→ остатки
```

После завершения этапа основная работа отдела снабжения должна выполняться через EnterpriseOS.

на площадку до построения полноценного фундамента снабжения. Текущий

### Критерий готовности 3.1A

Сотрудник подаёт заявку, EOS её сохраняет и разбирает, снабжение сопоставляет товары, утверждает количество, а система фиксирует запрошенное, отправленное и долг.

Критерий закрыт ручным end-to-end сценарием: сотрудник подаёт заявку, EOS
сохраняет и разбирает её, снабжение сопоставляет товары, утверждает план,
вручную фиксирует отправленное, а система хранит запрошенное, утверждённое,
отправленное и долг.

`PARTIALLY_FULFILLED` считается завершённой заявкой: незакрытый объём больше
не удерживает исходную заявку в активной работе. Дальнейшая работа с этим
объёмом ведётся через долг подразделения.

Фактическое количество может быть как меньше, так и больше запрошенного:

- запросили 10, отправили 8 — заявка исполнена частично, долг 2;
- запросили 50, отправили 100 — заявка исполнена, долг 0.

Исходная потребность подразделения сохраняется, а поле «Отправить» означает
фактически отправленное количество.

Основное исполнение Stage 3.1A сознательно остаётся ручным, при этом
жизненный цикл периодов автоматизирован через Automation Core. В backlog
перенесены 5/10-минутные таймеры, edit lock, пользовательское уточнение
неизвестной единицы, очередь mapping candidates и настройка кодов
подразделений. Критерий готовности от них не зависит: основной сценарий уже
выполняется через явные действия пользователя, уникальность заявки и
optimistic locking.

# Общие критерии завершения этапа 3

- [ ] Подразделения подают заявки через EOS.
- [ ] Пользовательский ввод автоматически нормализуется.
- [ ] Маппинг обучается на реальных заявках.
- [ ] Снабжение видит запросили / отправили / долг.
- [ ] Долги не теряются между циклами.
- [ ] Остатки поступают из iiko.
- [ ] Документы создаются в iiko.
- [ ] Документы автоматически печатаются.
- [ ] Закупки распределяются по поставщикам.
- [ ] Заказы отправляются через EOS.
- [ ] Ответы и PDF поставщиков связаны с заказами.
- [ ] Накладные, оплаты, приёмка и приход связаны.
- [ ] Видно, закуплена ли вся потребность.
- [ ] Видна задолженность перед поставщиками.
- [ ] Любая неоднозначность попадает руководителю.
- [ ] Ошибки не исчезают без решения.
- [ ] Система защищает товарный и денежный поток.
