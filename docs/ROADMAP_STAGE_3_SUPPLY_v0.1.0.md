# Цель этапа

Перенести снабжение в EnterpriseOS и построить сквозную систему:

```text
Заявки
→ обработка
→ перемещения
→ долги
→ закупки
→ поставщики
→ накладные
→ оплаты
→ приёмка
→ iiko
→ остатки
```

После завершения этапа основная работа отдела снабжения должна выполняться через EnterpriseOS.

### Критерий готовности 3.1A

Сотрудник подаёт заявку, EOS её сохраняет и разбирает, снабжение сопоставляет товары, утверждает количество, а система фиксирует запрошенное, отправленное и долг.

Основной критерий подтверждён ручным end-to-end сценарием: сотрудник подаёт заявку, EOS
сохраняет и разбирает её, снабжение сопоставляет товары, утверждает план,
вручную фиксирует отправленное, а система хранит запрошенное, утверждённое,
отправленное и долг.

`PARTIALLY_FULFILLED` считается завершённой заявкой: незакрытый объём больше
не удерживает исходную заявку в активной работе. Дальнейшая работа с этим
объёмом ведётся через долг подразделения.

Фактическое количество может быть как меньше, так и больше запрошенного:

- запросили 10, отправили 8 — заявка исполнена частично, долг 2;
- запросили 50, отправили 100 — заявка исполнена, долг 0.

Исходная потребность подразделения сохраняется, а поле «Отправить» означает
фактически отправленное количество.

Основное исполнение Stage 3.1A сознательно остаётся ручным, при этом
жизненный цикл периодов автоматизирован через Automation Core. Отдельно
перечисленный backlog 3.1A не входит в текущий эксплуатационный критерий
закрытия и не блокирует переход к Stage 3.1B.

### Production-confirmed zero semantics

Для активного EOS product с активным `CONFIRMED IikoProductMapping`, активного
`CONFIRMED SOURCE` и полностью успешного SOURCE snapshot targeted GET с
конкретными `store + product` вернул `rows=0`. Это зафиксировано как
production evidence того, что успешный полный `balance/stores` опускает товар
с нулевым остатком.

Правило расчёта:

```text
полностью SUCCEEDED SOURCE snapshot
+ active CONFIRMED product отсутствует среди snapshot lines
→ available_quantity = 0
→ transferable_quantity = 0
→ deficit_quantity = requested_quantity
→ unavailable_reason = null
```

`PARTIALLY_SUCCEEDED` и `FAILED` snapshot не используют zero semantics.
Отсутствие успешного snapshot, неподтверждённые product/SOURCE mapping,
unit mismatch и остальные contract errors сохраняют `BLOCKED`. Реальная
snapshot line, включая отрицательное количество, обрабатывается как прежде;
из отрицательного остатка переносить можно `0`.

Production-проверка stock calculation:

- «Молоко для коктейлей и кухни»: requested **12 л**, available **0**,
  transferable **0**, deficit **12**;
- «Салфетка бумажная белая 24*24»: requested **3 уп**, available **4**,
  transferable **3**, deficit **0**;
- «Пергамент»: unit исправлена на **шт**, requested **1 шт**, available **0**,
  transferable **0**, deficit **1**.

caller-generated UUID в минимальном окне даты документа, сверяет critical
поля с сохранённым deterministic write payload и не выполняет POST.
Production reconciliation пока не подтверждён.

Controlled production probe от 11.08.2026 дал новый UUID, валидный routing,
HTTP `409` с ответом `Cannot find InternalTransfer document by id <UUID>`, а
последующий read-only GET по UUID вернул `MATCHES 0`.

POST `/api/v2/documents/internalTransfer` **не подтверждён как create
endpoint**. Реализация `create_internal_transfer` и controlled write удалена;
этот POST нельзя использовать для создания новых документов. Новые write
probes не выполнять. Подтверждение routing contract не означает завершения
Stage 3.1B / 5 или всего Stage 3.1B.

Непосредственный следующий шаг:

1. Подтвердить read-only reconciliation `OUTGOING_INVOICE` в production без
   новых write probes.
2. Затем реализовать идемпотентную workflow-интеграцию; к кнопке «Отдать в
   работу» write path до этого не подключать.
3. После этого передать документ по цепочке `n8n → Print Agent` для
   автоматической печати.

Эксплуатационная цель до отпуска — замкнуть цепочку:
`автор заявки → mapping → SOURCE → stock calculation → iiko transfer document
→ print`.

- [ ] Создать отдельную сущность перемещения с источником, назначением,
      строками, плановым и фактически переданным количеством.
- [ ] Сформировать и подтвердить документ iiko через версионируемый provider,
      transactional outbox и идемпотентную обработку результата.
- [ ] Сформировать PDF в EOS, передать его в Print Agent и сохранить статусы
      и журнал печати.
- [ ] Зафиксировать получателя и подтверждение фактической передачи.
- [ ] Принять и сохранить возвращённый подписанный документ, связанный с
      версией перемещения и документа iiko.
- [ ] Расхождение количества, отсутствие подписи или потерянный документ не
      должны молча закрывать заявку или долг; создаётся явное исключение.
- [ ] Повторная доставка технического события, повторная печать или повторная
      загрузка того же документа не создают повторное покрытие долга.

Утверждённое правило фактического погашения долга:

> Отдельное погашение долга через перемещение не уменьшает долг до
> подтверждения фактической передачи и возврата подписанного документа.

Создание перемещения, успешная запись документа в iiko и печать сами по себе
не создают debt coverage. Уменьшение долга выполняется отдельным
идемпотентным событием только после выполнения обоих условий: фактическая
передача подтверждена и подписанный документ возвращён и связан с
перемещением.

# Общие критерии завершения этапа 3

- [ ] Подразделения подают заявки через EOS.
- [ ] Пользовательский ввод автоматически нормализуется.
- [ ] Маппинг обучается на реальных заявках.
- [ ] Снабжение видит запросили / отправили / долг.
- [ ] Долги не теряются между циклами.
- [ ] Остатки поступают из iiko.
- [ ] Документы создаются в iiko.
- [ ] Документы автоматически печатаются.
- [ ] Закупки распределяются по поставщикам.
- [ ] Заказы отправляются через EOS.
- [ ] Ответы и PDF поставщиков связаны с заказами.
- [ ] Накладные, оплаты, приёмка и приход связаны.
- [ ] Видно, закуплена ли вся потребность.
- [ ] Видна задолженность перед поставщиками.
- [ ] Любая неоднозначность попадает руководителю.
- [ ] Ошибки не исчезают без решения.
- [ ] Система защищает товарный и денежный поток.
