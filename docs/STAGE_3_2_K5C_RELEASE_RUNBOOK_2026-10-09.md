# K5C — ограниченный выпуск: runbook и release review

09.10.2026, Asia/Yekaterinburg. **На review. Commit, push, deployment и денежные
изменения production не выполнялись.** Владелец принял сверку 47/49 как основание
готовить ограниченный выпуск, не как разрешение публикации всей выборки.

## Состав и границы выпуска

- Происхождение во всех проекциях: **«Расчёт EOS по ТТК»**. iiko предоставляет
  ТТК и денежный складской учёт; готовая API-ССН не обнаружена. Историческая
  себестоимость продаж, ССС изделия и валовая прибыль не используются как ССН.
- 47 строгих совпадений — исследовательская выборка с независимым скрином Office,
  не начальные данные migration. Все входы/расчёты привязаны к source UUID.
- Артикулы **76243 / 76242 (X3)** исключены: backend отклоняет подтверждение;
  таблица, карточка и история скрывают сумму даже при старом подтверждении.
  Guard использует установленные source UUID (evidence keys 3bc212001fae4a31 /
  e0d033c3e736fcba), не display name или изменяемый артикул.
  Снятие исключения требует отдельного review метода складской ССС эклера против
  разложения по ТТК и точного подразделения. Название изделия не создаёт mapping.
- Шесть изделий из выборки отсутствуют в EOS; этот выпуск не добавляет их.
- K3, K5B, Supply, Sales, цены и рецептуры не меняются.
- Нет seed сумм, запусков или расписаний. Действие Automation Core доступно
  техническому оператору, но migration/страница/подтверждение его не запускают.

## Условия допуска к release

1. Review diff всего K5C package; сохранить чужие K5A report/evidence и остальные
   dirty/untracked файлы. Не выпускать из рабочего dirty checkout без отдельно
   согласованного точного состава и SHA/image artifacts. SHA здесь не выдумывается.
2. Повторно установить production HEAD/Alembic/services. Нужен существующий head
   **20261009_0078** для migration 0079; при другом head — STOP и новый review.
   Ранее полученные сведения о production — исторические, не новый preflight.
3. Для production migration: свежая проверенная резервная копия, её checksum,
   подтверждённый способ восстановления и согласованный recovery window.
4. Отдельное разрешение commit/push/deployment. Этот runbook не является таким
   разрешением. Browser/business smoke ниже должен быть выполнен на целевой сборке
   до включения подтверждённых денежных показателей.

## Миграция 0079 и восстановление

[0079](../backend/api/alembic/versions/20261009_0079_product_costs.py) создаёт только
`product_cost_observations`, `product_cost_verifications`, FK, constraints, index и
append-only triggers. Не пересчитывает/перезаписывает существующие business tables,
не создаёт automation schedules, не меняет источники iiko или права людей в БД.

На отдельной тестовой PostgreSQL проверены цикл 0078 → 0079 → 0078 → 0079,
запрет UPDATE/DELETE истории, tenant/source/product FK, конкуренция одинакового
execution, сохранение результата вместе с terminal execution/outbox и запрет
повторной обработки terminal execution. Финальные результаты — ниже.

Будущий оператор после backup/preflight и отдельного разрешения выпуска:

```powershell
Set-Location C:\eos
$ErrorActionPreference = 'Stop'
# Сверить согласованные SHA/images и сохранить rollback images трёх сервисов.
# Остановить новые ручные K5C запуски; дождаться terminal активных execution.
docker exec eos-api alembic current
if ($LASTEXITCODE -ne 0) { throw 'STOP: migration preflight failed' }
# Выполнять после доставки согласованной сборки API с migration 0079:
docker exec eos-api alembic upgrade 20261009_0079
if ($LASTEXITCODE -ne 0) { throw 'STOP: migration failed' }
docker exec eos-api alembic current
if ($LASTEXITCODE -ne 0) { throw 'STOP: migration verification failed' }
# Проверить head == 0079, API/database health, api/automation-worker/frontend.
# Не выполнять refresh, bulk probe, schedule create/enable на этом шаге.
```

Команды здесь не выполнялись. Сборка/замена только api, automation-worker и frontend
по существующему deployment flow; n8n/БД/volumes не пересоздавать.

**Rollback:** сначала остановить K5C сбор/регламенты, вернуть сохранённые images
только затронутых сервисов. При сохранённой истории оставить schema 0079:
`downgrade 0078` намеренно отклоняется с `COST_HISTORY_EXISTS`. Не удалять историю
для обхода защиты. Старый код не использует новые таблицы. Пустая schema допускает
downgrade, но только после отдельного решения; аварийное восстановление backup
имеет последствия для всех данных после backup и не запускается автоматически.

## Ручной пилот и безопасная проверка

До пилота технический оператор и ответственный сотрудник совместно устанавливают
source, точные UUID изделий, дату/часовой пояс, UUID подразделения (если влияет на
ТТК) и **конкретные UUID складов либо доказанный полный агрегат всех складов**.
Название «ЦЕХ Полярная Производство» само по себе не подтверждает UUID/aggregate.
Не выбирать похожий по названию склад. Неизвестный контекст — только закрытая
проверка, без подтверждения и публичной суммы.

После отдельного разрешения пилота начать с 1–3 существующих UUID вне X3.
Технический enqueue `POST /products/costs/refresh` возвращает 202 — команду получил
Core, а не готовую стоимость. Execution/outbox/worker остаются существующими;
обычная страница читает только EOS DB. Не запускать scripts массовой разведки
как production scheduler. Рабочий 49-row evidence не импортировать в БД.

Права:

- PRODUCT_COST_READ: ADMIN, HEAD_OF_PRODUCTION, CHEF_CONFECTIONER.
- PRODUCT_COST_REVIEW и PRODUCT_COST_CONFIRM: те же ответственные роли,
  с существующими active employee/production-context и write guards.
- Сбор: TECHNICAL_ADMIN. Доступ к каталогу/ценам не даёт доступ к стоимости.
- SELLER и остальные роли: нет сумм, ингредиентов или кандидатных денежных данных;
  прямые cost endpoints должны возвращать 403.

В карточке нажать **«Проверить расчёт»**. `GET /products/{id}/costs?review=true`
явно авторизует REVIEW, показывает отдельную кандидатную ССН, количество/единицу/
цену ингредиента/вклад и предупреждения. Кандидатная сумма не попадает в обычную
колонку «Себестоимость». Неполный/устаревший снимок не имеет кандидатной суммы
или подтверждения. X3 получает EXCLUDED и не имеет подтверждения.

Ответственный сравнивает Office на ту же дату/контекст, действующую версию ТТК,
вложенные полуфабрикаты, количество и основные единицы. Для подтверждения нужно:

1. Ввести **ССН из Office**, без переноса ССС/СПП/Sales стоимости.
2. Явно выбрать наличие звёздочки: «есть»/«нет», без значения по умолчанию.
3. Подтвердить точный склад/полный набор складов и подразделение/дату/ТТК.
4. Записать основание проверки (дата Office, выбранные склады/подразделение,
   версия и результат сверки; не вставлять credentials или internal payloads).
5. Нажать **«Подтвердить этот расчёт»**. Backend проверяет exact latest snapshot,
   content hash, свежесть ≤2 часов, полноту, совпадение суммы до копейки и X3 guard.
   Расхождение/смена снимка — 409, подтверждение не сохраняется.

Подтверждение append-only, с автором/временем/audit. Оно относится только к
этому снимку; `warehouse_confirmed=true` — явное человеческое утверждение
проверенного контекста, не автоматический mapping склада. При неизвестном контексте
этот checkbox не отмечать. Подтверждение не включает сбор или расписание.

## Статусы и отсутствие данных

| Состояние | Обычная таблица/карточка | Режим проверки |
|---|---|---|
| Нет наблюдения | Нет подтверждённой себестоимости | Нет кандидата/подтверждения |
| UNVERIFIED | Сумма скрыта | Кандидат только для сверки; склад/оценочность неизвестны до проверки |
| INCOMPLETE | Неполные исходные данные, сумма скрыта | Нет суммы/подтверждения; никакого нуля вместо отсутствия |
| STALE / время из будущего | Сумма скрыта | Подтверждение недоступно; нужен новый ручной снимок |
| EXCLUDED (X3) | Сумма скрыта | Метод оценки не установлен; подтверждение запрещено |
| VERIFIED, точный текущий снимок | Итог/детализация доступны; происхождение «Расчёт EOS по ТТК» | Есть независимая сверка склада и оценочности |
| VERIFIED, оценочный | Сумма со звёздочкой и пояснением | Флаг известен из exact Office подтверждения |
| Несколько контекстов | Сумма скрыта, выбрать контекст в карточке | Проверка только выбранного контекста |
| Новый снимок после подтверждённого | Новая сумма скрыта; старое подтверждение не переносится | Повторная независимая сверка |

Ингредиент без денежного остатка, неизвестные единицы, конфликт/цикл ТТК или
неизвестный размер/подразделение дают NULL. Подтверждённый source zero отличается
от отсутствия стоимости и требует отдельной проверки. История подписана как
историческая, не используется вместо текущей суммы.

## Автоматизация после пилота

Массовый сбор и hourly schedule **по умолчанию не создаются и не включаются**.
После отдельного решения можно настроить существующий регламент на фиксированные
UUID/контекст, только с предварительными exact Office verifications и явным
`allow_updates=true`. Это разрешает сбор, не автоматическую публикацию суммы.

Для будущей автоматической публикации нужен доказанный источник оценочности
каждого нового снимка и подтверждённый складской контекст. Пока такого источника
нет, каждый новый снимок UNVERIFIED и скрыт. 47/49 и approval метода не снимают
это ограничение; эмпирические правила pooling/rounding не объявляются API-ССН.

## Browser/business smoke до включения денег

- Ответственные роли: открытие карточки, обычная сумма скрыта, режим проверки,
  ингредиенты/единицы, контекст и даты; подтверждение exact снимка после Office.
- Без выбранной оценочности/checkbox складов/контекста/основания кнопка disabled;
  duplicate submit защищён; backend прямой запрос без доказательств отвергает.
- Смена snapshot после открытия формы — 409 и понятная русская ошибка; stale,
  missing stock, unknown units, X3, zero и оценочный snapshot проверены отдельно.
- SELLER/прочие роли: раздел и кандидат отсутствуют, прямые GET/POST — 403;
  другой tenant — недоступен; API не содержит stock rows/secrets/provider payload.
- После подтверждения: сумма/звёздочка/ингредиенты в обычной карточке, источник
  «Расчёт EOS по ТТК»; автор/дата доступны в сохранённой истории/audit.
- После нового ручного сбора: сумма снова скрыта. Ошибка не показывает прошлую
  хорошую сумму как текущую. Количество расписаний/массовых запусков не выросло.

Browser/business acceptance и production migration в этом проходе не выполнялись.
