# K5C — исследование стоимости по расходным накладным iiko, 12.10.2026

Статус: **research / review; новый метод расчёта не принят; публикация запрещена**.
Только чтение iiko через существующий клиент с production-сервера. Код EOS, production-файлы, БД, права, цены K3, ТТК, Supply и Sales не изменены; задания Automation Core и full-sync не запускались. Новые товары не создавались. X3 остаются заблокированными. Изменения предыдущей задачи сохранены отдельно и этим исследованием не одобряются.

## Вывод

Сентябрьский Excel формируют **321 расходная накладная плюс один акт реализации**, а не только расходные накладные. Выручка и общий учётный расход воспроизведены до копейки. Сумма передачи в документе отличается от учётного расхода: принимать `price` или `sum / amount` за себестоимость нельзя. Проверенные API позволяют получить последнюю сумму передачи, но **получение последней подтверждённой учётной стоимости отдельного готового изделия пока не доказано**. Статус `PROCESSED` и флаг `recalculateSumByCost=true` не подтверждают окончательный метод оценки каждой позиции.

## Последняя стоимость и вариант EOS — предложение, без реализации

За01–12.10 прочитано120 проведённых расходных накладных целевого склада,82 UUID продукции с положительным количеством. Сумма документов1 220 364,51 ₽, учётный расход410 529,06 ₽. [82 наблюдения последних строк передач](evidence/STAGE_3_2_K5C_OUTGOING_COST_2026-10-12_latest_transfer.csv) — диагностические данные, не готовая загрузка себестоимости. Выбиралось максимальное dateIncoming в проверенном окне; это не поиск последней передачи за всю историю. При нескольких строках/документах с одинаковым временем потребуется явное агрегирование/разрешение неоднозначности; автоматически публиковать эту выборку нельзя.

Предлагаются отдельные показатели:

1. **«Учётная стоимость изделия по документу»** — только после получения стоимости списания именно готового UUID и основной единицы, связи с document UUID и проверки оценки. Дата документа, дата наблюдения, склад, номер, период и тип источника обязательны. Сейчас показатель NULL: cost документа нельзя пропорционально раздать изделиям, а текущую ТТК нельзя использовать для восстановления исторического списания.
2. **«Сумма передачи за единицу»** — доступный самостоятельный показатель `sum/amount` по строке проведённой расходной накладной. Рядом дата и номер документа, отдельная исходная price; без подписи «себестоимость». Если бизнес не нуждается в этом показателе, его не показывать в основной колонке каталога.
3. **«Учётный расход за период»** — сверенный документный показатель для сентября; это исторический расход периода, не актуальная ССН. Средневзвешенная стоимость изделия допустима только при подтверждённом UUID-составе отчёта и согласованных единицах.
4. **«ССН iikoOffice на дату»** и **«Расчёт EOS по ТТК»** — отдельные источники/метрики. Не перезаписывают учётную стоимость или передачу. Текущий отклонённый метод EOS не получает статус принятого из-за совпадения итогов нового отчёта.

В «Продукции» рядом с ценой K3 предлагается колонка подтверждённой учётной стоимости с подписью источника/даты и раскрытием: UUID изделия и единица, склад, документ/дата, quantity, документная сумма, учётный расход позиции, оценочность, период и время получения. Для периода показывать отдельно «Сентябрь2026», не «актуальная». Если доступна только сумма передачи, основной показатель себестоимости остаётся «Не подтверждена»; отдельная строка в раскрытии подписана «Сумма передачи». Ингредиентная расшифровка исторического cost доступна только при доказанной связи с исходным готовым UUID/строкой; рецепт EOS показывается отдельно с собственным источником и датой.

Для изделия без передачи в выбранном периоде: «Нет передач за период», стоимость NULL. Можно отдельно показать ранее подтверждённую стоимость с её исходной датой и пометкой устаревания после согласования срока актуальности; отсутствие в01–12 октября не доказывает отсутствие во всей истории. Не использовать ноль, K3, defaultSalePrice, другие склады или новую оценку ТТК как незаметную замену. Не создавать новый товар при неизвестном UUID. X3 всегда остаётся заблокированным до отдельного решения о методе оценки.

Для дальнейшего исследования/приёмки нужны либо read-only выгрузка проводок/документных затрат с UUID готового изделия, количеством, основной единицей, cost, UUID/датой документа и признаком/методом оценки, либо согласованный доступ к уже существующему отчёту iikoOffice с этими полями. B_VOTR — выявленное отсутствующее право, не инструкция менять доступ. Позиции акта0255 также нужны для независимого подтверждения17 единиц. После этого следует сверить5–10 документов по стоимости каждой готовой позиции, повторить месячные91 позиции и отдельно проверить последние документы.
